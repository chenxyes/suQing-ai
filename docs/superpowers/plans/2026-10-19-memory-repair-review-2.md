# 第 2 项修复审阅：记忆写入与召回限制

用户已于 2026-10-19 接受本项本地修复。第 1 项已接受；本项没有提交、推送或部署，没有操作服务器。

原问题：被标为删除、归档或禁止提及的记忆，仍可能经关键词、向量、置顶、旧摘要或画像进入聊天；单条、批量和编辑入口的存储过滤不一致，手动新增被过滤后甚至可能误取上一条记录并重新激活。

## 本项行为

- 聊天、主动消息、摘要、反思与相似记忆匹配共用可召回规则，排除受限条目，并保留敏感标记供下游判断。管理列表保留原记录。
- 单条、批量、编辑统一检查内容和关键词；写入被拒时返回失败。接口响应和事件图谱使用实际保存后的内容，不再将被拒绝的写入计作成功。
- 新派生记忆记录实际输入记忆 ID；来源被删除、修改或禁止提及时，依赖摘要停止召回。重新恢复源记忆不会自动批准旧派生内容。
- 撤销记录持久版本号和会话边界：生成期间发生撤销，迟到的摘要、反思或抽取结果不能写回。空记忆来源的会话摘要也绑定生成版本，避免后续撤销绕过。
- 内容编辑清除旧向量；反思编辑统一走受控入口。仅有一条输入的反思更新，也能正确保留本次新内容并使旧派生失效。
- 微信重新绑定时迁移、合并撤销限制；不能因为用户 ID 改变恢复旧画像，迁移前的迟到生成结果也不能写回。
- 自动到期清理保留仍被其他摘要引用的源记录，避免尚在保留期内的周/月摘要因来源缺失而失效。用户显式删除仍使依赖失效。

## 需要接受的取舍与后续工作

1. **暂时减少个性化。** 旧画像没有字段来源；同一角色发生撤销或内容修正后，整份画像保守停止注入。旧无来源摘要同样被屏蔽。不是删除数据，也不会自动恢复；第 3 项需要建立可验证来源后重建。
2. **不等于擦除聊天历史。** 原始聊天、即时上下文及管理备份仍保留；本项限制长期记忆召回及后台重新生成。若近期原话仍在即时上下文中，模型仍可能看到它。
