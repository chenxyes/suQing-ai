# 第 3 项修复审阅：事实主体、原话证据与纠错

用户已于 2026-10-20 接受本项本地修复，并授权添加本地 commit。第 1、2 项已接受。本项没有提交、推送、部署或修改服务器。

## 原因与修复

原抽取器把对方发言和角色回复混在一个文本输入中，要求模型统一写成“他……”，写入时却没有主体或原始消息校验。反思同样混合不同说话人的经历，提示中没有真实消息 ID、记忆 ID；注入聊天时又把所有记忆统一放进“关于他的片段”。这几处叠加，能够把角色自己的妹妹变成对方的妹妹。

新路径的变化：

- 聊天入口捕获实际保存的消息 ID，传给抽取器；模型输入明确区分 ID、user/assistant 和原文。没有来源 ID 的旧调用不会猜测“最近那条消息”来补证据。
- 新记忆区分 `user`、`companion`、`shared`；旧数据默认 `unknown`。数据库核验来源是否属于当前角色及所有者、是否为实际提供的消息、是否真实而非合成，以及原句是否确实存在。
- 对方事实只能引用对方的独立第一人称陈述；角色事实只能引用角色自身陈述；共同事实需要双方明确陈述。引述、假设、问题、简短附和和已撤回的说法保守拒绝。
- 实际存储核验后的原句，不直接采用模型自由改写。这样“我没有妹妹”不会因为模型输出“他有妹妹”而反转含义。主体与证据一起保存在记忆中，管理 API 可查看。
- 反思提示包含实际展示的记忆 ID，不能更新模型未见过的记录。新建和纠错都走同一个证据写入入口；保持置顶、锁定、撤销版本和来源依赖约束。
- 同一用户、角色和主体的规范化原句去重；不同主体或未知归属之间不做模糊合并。重复结果不重复建图、计数或触发保存成就。
- 明确纠错且能对应原事实时，在事务内保存替代记录，将旧记录标为 `contradicted` 并使旧派生摘要失效。保留历史，不直接删除旧事实；无关更正、猜测 ID 不允许撤销记录。
- 聊天提示分开标注对方自述、角色自述、双方陈述及待核实内容；旧摘要不再被要求当作真实共同经历。现有事件图谱只支持对方主体，因此角色、共同及未知归属记忆暂不写入该图谱。
- 自动画像不再独立调用模型自由推测职业、爱好等字段，而是从本轮已核验的对方记忆形成完整原句备注。旧画像保留在管理端；聊天只读取有有效来源或通过认证接口明确手工编辑的字段。

需要明确的取舍：

1. 这是说话来源和归属校验，不是真伪认证；角色声称的经历也可能是模型编造的。未调用真实模型做长期准确率或自然度评测。
2. 规则有意保守，含蓄表达、省略主语、复杂引述和部分更正可能不被保存或自动处理。无法安全对应的纠错可通过现有管理界面处理，不会擅自猜测撤销目标。
3. 旧未知内容仍在独立待核实区，近期原对话仍可能进入即时上下文。本项不能保证模型在所有表达中绝不混淆，也没有自动清除全部历史污染。
4. 自动结构化画像字段暂不推断，只累积到完整自述记忆并更新本轮备注；认证界面的手动资料编辑仍可使用。原画像、旧备份保留。
5. 去重针对规范化原句，语义近义句不贸然合并；新证据记忆暂不写向量，以免向量与规范化正文不一致。向量来源、回填与混合检索由第 4 项统一修复。
