# 第 7 项本地修复审阅：虚构历史隔离与完整记忆迁移

用户于 2026-10-20 接受本项本地修复并授权提交到 `codex/memory-repair`；未授权推送或部署。第 6 项已按授权提交为 `11d0509 fix(works): preserve activity kinds and honest fallback progress`。

## 修复后的行为

创建角色、微信绑定/重绑和聊天消息都不再自动编造共同经历。角色自身的人生背景仍可照常生成和使用。管理员手动生成必须明确确认“虚构共同经历”；重复生成只追加，不覆盖原记录，也不再提高真实好感度。

模拟对话保留 `synthetic=1`，对应记忆保存 `memory_origin=synthetic` 和生成来源、对话 ID。它们可以在管理页面查看，但不会进入聊天上下文、事实证据、长期记忆召回、画像分析或标注语料导出。编辑内容、来源标签或置顶都不能把虚构记录变成真实记忆。生成后的整批写入核对归属和召回版本；生成期间被清空、撤销或换绑时拒绝写入。

角色 JSON 升级为 v2。记忆和对话以 ID 游标分批读取，不再只导出前 200 条活跃记忆。导出包含所有状态、主体、证据、来源、置顶/锁定/不提及标记、时间、依赖关系、向量及其元数据；导入重新映射记忆和对话 ID，整个新角色导入在单个事务中完成。向量原样转移不等于向量有效；仍须通过此前的模型空间和内容散列校验才可检索。

外部 JSON 本身不能证明历史真实。网页导入保留声明的主体和证据，但记忆及导入对话默认隔离，管理页面显示隔离状态。显式审阅的本地副本迁移可以信任已核对的历史，仍不能跳过说话人证据检查或解除原有删除、隐藏、虚构及依赖限制。旧 v1 文件可导入，缺失的主体证据保持未知，不自动补造。

角色备份页面增加“包含全部记忆与历史”选项，默认不勾选，避免分享人设时意外带出私人历史。网页导入上限为 32 MiB，超限明确报错。导入遇到隐私过滤不允许原样保存的内容时整批拒绝，不悄悄删行。

本地 `scripts/persona_transfer.mjs` 也支持旧数据库缺少新列的情况，无须先迁移原库。默认大小限制同网页，可用 `--max-import-mib` 显式提高至最多 256 MiB；更大的文件明确拒绝。分页限制的是数据库单次读取量，最终 JSON 仍会在内存中组装。

```sh
# 完整导出，只读取 INPUT.db，输出文件必须不存在
.superpowers/runtime/node_modules/node/bin/node scripts/persona_transfer.mjs export \
  --db INPUT.db --companion-id 1 --output-json NEW_EXPORT.json

# 目标用户须在 TARGET.db 中存在；新角色写入 NEW_COPY.db，原库不变
.superpowers/runtime/node_modules/node/bin/node scripts/persona_transfer.mjs import \
  --db TARGET.db --input-json NEW_EXPORT.json --output-db NEW_COPY.db --user-id 1
```

只有明确核对过历史后，才在本地导入命令追加 `--trust-reviewed-history --reviewed-sha256 <已审阅JSON的SHA256>`。散列绑定审阅过的文件，不能证明原作者诚实，也不会取消原有受限状态。网页接口不能设置这一信任选项。迁移工具用于在新副本中新增角色，不会原地覆盖线上角色，也不是完整服务器备份的替代品。

## 历史数据处理

新工具 `scripts/memory_synthetic_audit.mjs` 默认只读，生成所有来源不明记忆的 ID、归属、内容散列和审阅线索，不在报告中打印聊天正文。旧格式与同范围模拟话题精确匹配也只算嫌疑，不能自动定性。被改写、缺少话题或原始对话已清理的数据可能无法按此规则识别。

应用历史分类必须提供人工审阅清单，绑定源数据库/WAL 散列及逐行归属、内容散列和召回版本，并写入一个全新数据库副本。任一条目失败，整份清单回滚。原始数据库和旁边的文件不会被写入，原快照继续保留作为回滚依据。
