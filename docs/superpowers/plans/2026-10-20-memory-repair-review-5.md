# 第 5 项本地修复审阅：未成年人判定中的事实主体

第 4 项已接受并提交为 `78bc032 fix(memory): isolate vector spaces and repair retrieval maintenance`。本项位于本地修复分支 `codex/memory-repair`，已于 2026-10-20 获用户接受并授权本地提交。服务器和既有安全模式记录均未修改。

## 问题与修复

旧逻辑会把双方聊天送入一个只回答 yes/no 的分类器，并直接接受模型的 yes。角色谈到上学、对方催角色进校门时，模型可能把角色年龄归到对方，触发非恋爱安全模式。这会改变角色互动方式，是需要排除的一条“变得像机器人”的原因；本项不能证明所有表达问题都由它造成。

现在只把有明确 user/in 来源的消息作为候选证据，排除助手、未知或冲突的角色信息。模型必须返回结构化结论、消息来源和连续原文；每条引用都要与对应来源一致，并通过当下本人自述校验。裸 yes、伪造引用和只摘取假设/转述中的年龄词不能触发新锁定。

明确的当前年龄自述继续直接触发，无需模型。引用、第三方、回忆、假设、角色台词、代码块和说话人标签增加排除检查。独立复核还修复了以下边界：

| 输入示例 | 修复后 |
| --- | --- |
| 角色说学校经历，对方催角色进校门 | 不把角色经历作为对方年龄证据 |
| 我今年16岁请你记住 | 仍直接触发保护，不因后半句提到“你”漏检 |
| 我16岁吗？ / 我是不是初中生？ | 不作为肯定自述 |
| 并不是我16岁，是我妹妹 / 我不是初中生 | 不通过肯定自述校验 |
| 我今年18岁，我读高三 | 不单凭中学在读推断未满18岁 |
| 当前说已经19岁，旧消息说17岁 | 本次不使用旧年龄重新判为未成年 |

当前明确成年年龄只限制本次新判定，不解除持久化状态。同条消息如果仍有明确未成年年龄自述，保护判定优先，未把冲突声明当作自动解除依据。

## 使用影响与边界

- 微信和网页聊天都沿用现有检测入口；明确触发时，数据库状态和本轮 prompt 状态一起进入安全模式。网页探针跳过检测和写入。
- 现有安全模式保持粘性。服务器上过去的误锁不会被这次本地修复自动清除，仍需现有的显式年龄声明流程；没有批量修改历史状态。
- 普通无相关词消息和明确年龄规则保持零额外分类调用。弱信号的输出预算从 5 增至 400 token，用于容纳可核对的 JSON，实际费用取决于模型服务。
- 中文语境检查仍有边界：复杂跨句角色扮演、隐含主体、后置否定、跨轮纠正，以及否定或引用中的真实自述，可能漏检或误判。学校生活推断仍依赖模型，不能把离线用例通过当成分类准确率或线上安全保证。
- 本项没有把普通聊天年龄变成正式年龄核验，也没有修改安全模式的解除接口或关闭保护机制。
