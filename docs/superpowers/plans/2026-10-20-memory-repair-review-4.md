# 第 4 项本地修复审阅：向量、混合召回与维护

第 1～3 项已经用户接受并提交为 `29712d7 fix(memory): validate embeddings and preserve fact provenance`。本文所列第 4 项已于 2026-10-20 获用户接受并授权本地提交，位于 `codex/memory-repair`；未推送、未部署。第 5、6 项候选改动仍单独保留。

## 修复结果

1. **不同来源的向量不再混算。** 每条新向量保存 provider、model、dimension、endpoint 指纹及正文 SHA-256；正文修改会清除旧向量和元数据。没有来源标记的旧向量保留在数据库，但不参与语义比较。查询向量还必须对应当前查询正文。配置在请求等待期间变化，不会把旧请求的结果标成新模型。
2. **语义和关键词共同参与排序。** 微信和网页聊天统一使用混合检索，中文采用双字片段与词面匹配；无向量的相关事实不会因为语义结果非空而被跳过。相关性优先于置顶，最多两条无关置顶作为兜底，真正相关的置顶事实不受该配额限制。衰减、重要度和权重参与排序。
3. **新事实安全索引。** 提取、反思及日程归档对数据库最终正文生成向量。写回时重新检查归属、召回资格、撤销版本和正文，拒绝等待期间发生编辑、删除或重新绑定后的旧结果。索引失败保留事实；重复或被拒绝的提取候选不调用索引。图谱同步处理在异步索引之前完成，避免新增等待点引入旧正文写入。
4. **使用时间在聊天实际采用时更新。** 普通检索、管理预览和网页探针不更新使用次数；微信经过敏感内容筛选、主动消息经过素材冷却后，在调用回复生成前更新实际选中的条目。直接危机答复不更新。这表示“被放入生成请求”，不表示模型一定引用或消息已经送达。
5. **维护不再漏批次或破坏来源。** 衰减按 ID 分页，处理全部候选，固定本轮上界；不再循环处理前 200 条。压缩 importance 从非法的 15 改为 10，摘要和来源标记在同一事务写入，保留原始来源。已有月摘要或没有周摘要时仍可执行旧事实压缩。同月多批次可继续处理。
6. **压缩只隐藏模型确实看到的来源。** 按完整行及 12,000 字符预算拆批，每批至少三条。超长单条及不足三条的批次继续保留为原文召回，不把被截断的尾部标成已压缩。撤销来源会使派生摘要失效；摘要不可用时，其余合法来源可以恢复普通召回。
7. **保留摘要与证据所需对话。** 小时清理保留最近八天、每个角色最新 100 条，以及被记忆证据引用的旧消息，避免日摘要生成前先裁掉大部分当天对话。

## 回填工具与历史副本

`scripts/memory_vector_backfill.mjs` 默认只读审计，不迁移 schema、不联网。只有显式 `--apply --output-db` 才创建新副本并请求向量；续跑必须加 `--resume`，且副本标记与原始来源身份相符。工具拒绝把源文件或运行库作为输出，检查来源、正文和撤销版本；失败条目可以重试。输出只包含数量、ID 与安全错误代码。

仅审计示例：

```sh
node scripts/memory_vector_backfill.mjs --db /absolute/path/offline-copy.db
```

## 已知范围

- 尚未验证真实 embedding 凭据、服务连通性和中文语义质量；没有运行在线回填或自然度对照实验。
- 压缩减少普通召回中的重复来源条目，保留原文供追溯，因此不承诺缩小数据库文件；模型摘要本身仍可能遗漏细节。
- 八天保留窗口并不等于长期停机后的自动补跑；日摘要原有的条数和字符上限仍存在，高频对话不保证全部进入摘要。
- 自定义 embedding 服务初始维度未知，每次回填进程可能先发一次有效请求确定维度，再跳过同空间的已有向量。
- 所有更改仅在本地修复分支。远端 Docker、下载的原始快照和 main 分支均未修改。
