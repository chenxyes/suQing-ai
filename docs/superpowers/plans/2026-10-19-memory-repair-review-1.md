# 第 1 项修复审阅：Embedding 配置与故障状态

用户已于 2026-10-19 明确接受本项本地修复。尚未提交、部署或修改服务器配置。

原问题是：含中文等非法字符的密钥被显示成“已配置”，实际请求在构造请求头时持续失败；原生向量模型/密钥/维度还直接读取环境，与数据库中的设置覆盖规则不一致。

本项变更：

- 原生 Embedding 的 provider、密钥、模型和维度统一采用数据库设置优先、环境回退的规则。显式空密钥不能偷偷回退到其他密钥。
- 请求前拦截空密钥、非 ASCII/含空白密钥、未知 provider、非法模型和维度，返回可读原因，日志不记录密钥、用户文本或上游响应正文。
- 区分“配置格式合法”和“服务调用成功”。设置页显示未验证、最近成功或最近失败；已登录状态接口提供本进程当前配置的调用/失败次数和时间。更换配置或重启进程后重新验证。
- 原生配置可点击已有“测试已保存配置”按钮；测试明确执行一次模型服务调用。自定义配置的探测也纳入同一健康状态。
- 校验返回向量非空、数值有限且非零；原生响应必须符合请求维度，停止静默截断；自定义向量保留服务完整返回维度。
- 新回归已接入 CI，未新增项目依赖或改动 lockfile。

本项修改文件：`.github/workflows/ci.yml`、`src/providers/embedding.mjs`、`src/api.mjs`、`public/app/setup.html`、`scripts/embedding_config_check.mjs`、`scripts/custom_provider_check.mjs`、`scripts/setup_ui_check.mjs`。
