# 中转配置、聊天可靠性与 AWS 发布

用户于 2026-09-18 明确批准本方案实施；合并和线上部署仍须另行批准。

## 范围与行为

OCR/vision、ASR、TTS、生图和 embedding 各有独立的自定义 OpenAI 兼容 provider，配置 URL、API key、模型；TTS 支持 voice。保留现有厂商协议。URL 表示 API base（通常含 /v1），不支持任意协议自动猜测。设置页可以保存、回显非秘密配置、测试连接。数据库设置优先于环境默认值，密钥不回显，留空保留已存密钥。配置须先整体验证后保存。生图、embedding 的端点适配不改变记忆提取、召回、排序或存量向量。

聊天请求记录有效 provider/model、结束原因、空响应类别、尝试次数与耗时，不记录 key、prompt 或推理内容。空响应不作为成功：可恢复故障有限重试，拒绝/过滤等明确不可恢复情况不盲重试。SDK 与业务层重试不得叠乘；超时应可配置且有合理边界。保持现有 generateReply 的字符串接口，集中标识兜底，防止错误回复作为正常对话持续反馈；不修改记忆算法。历史日志无法证明上游为空的具体原因，需要新诊断支撑。

CI 执行静态检查与回归测试。手动发布只允许验证过的 main 提交，用不可变镜像 digest 部署；production environment 审批通过才运行 SSH 发布。服务器持久卷、凭据、端口保持原样，部署健康检查失败回滚。审批保护需管理员在 GitHub 配置，缺失时应 fail closed。不得在本次实施中部署或修改服务器配置。

## 已核验证据与记忆建议

线上 v1.22.0 的 ai.mjs、providers/chat.mjs、memory.mjs、db.mjs 与初始提交 3de4e36 文件 hash 一致。所查 bot.log 中有 45 条兜底回复、0 条最终 chat 错误和 1 次超时重试。缺少 finish_reason，兜底也会进入历史，因此不能区分原始空返回和模型复述。

有效聊天配置是数据库 deepseek/deepseek-chat，环境模型 deepseek-flash 被覆盖。默认 Gemini embedding 配置含非 ASCII key，193 次 ByteString 编码错误导致关键词兜底。短于 8 字的输入跳过提取；关键词按空白分词不适合中文；7 条召回可有 5 条 pinned 占位。建议未来修复 embedding 配置和索引一致性、支持短句纠正、保留消息来源与事件时间、以矛盾检测替代纯相似去重、过滤过期事实。当前不改记忆实现或生产配置。

## 验证

本地 HTTP 假中转验证实际路径、认证、模型、响应与失败处理；覆盖配置保存/读取和隔离。聊天以空 content、空 choices、截断、拒绝、429、401、超时测试。部署脚本用隔离模拟 docker 验证成功和回滚，workflow 静态检查。PR 必须附验证结果、根因证据边界、审批配置步骤和独立审查结果。
