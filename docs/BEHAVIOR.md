# suqing 相处行为 V1

目标是让 suqing 亲自采用合适的相处方式。当前方法库覆盖受挫安慰、分享喜悦、双方争执修复；资料不会作为咨询教程直接展示给用户。五阶段目标见 [ROADMAP](ROADMAP.md)，实现范围见 [实施计划](superpowers/plans/2026-11-17-suqing-behavior-v1.md)。

## 启用与外挂方法库

默认关闭。在测试部署的环境配置中设置并重启服务：

```dotenv
BEHAVIOR_ENABLED=true
# 可选：评测时每份有效草稿都送审
# BEHAVIOR_REVIEW_MODE=all
# 可选：完整替换内置方法卡，使用部署者维护的本地目录
# BEHAVIOR_LIBRARY_DIR=/path/to/behavior-cards
```

设为 `false` 并重启即可停止 V1 回复和跟进。重新启用时，仍有效且未取消的预约可能继续执行。最新候选版本与真实模型回放见[验收记录](evaluations/2026-11-25-grounded-replies.md)。

内置目录为 `config/behavior/`。外挂目录支持 1–3 个 JSON 文件，每类场景一张卡；字段和长度由 `src/behavior_library.mjs` 校验。复制内置卡后修改 `when/actions/avoid/exit`，保留准确的 `source.repository/revision/path`。文件不超过 16 KiB，拒绝符号链接；损坏或不合规范时本轮退回普通聊天，不加载另一套方法掩盖错误。

这是部署者维护的方法配置，不能开放成用户上传后直接生效的指令入口。V1 场景和动作白名单固定，修改卡片文案不会自动增加新场景或工具能力。文件按需读取，修改无需重建向量索引；代码只挑选少量当前相关卡片。

内置内容参考 [狗头军师](https://github.com/shengjidaguai-china/goutoujunshi/tree/6db7354a4002dc7c448a9c87ffdad8132570c9d3)，固定来源版本为 `6db7354a4002dc7c448a9c87ffdad8132570c9d3`，改写为 suqing 执行的行动。MIT 声明保留在 `config/behavior/LICENSE.goutoujunshi`。不在运行时自动同步 GitHub 更新。

## 回复如何变化

1. 程序根据本轮输入、最近对话和近期行动筛选场景。普通闲聊不注入方法卡，只保留简短事实与边界约束；明确停止优先。
2. 启用 V1 时，现有 Inner OS 同一次调用只返回原有冲突信号和 `behavior` 候选；普通回合也不再向最终提示注入自由形式的独白，防止把想象当成事实。没有新增第三次策略调用；行为轮的预处理 token 预算至少为 480，仍可能增加延迟与成本。
3. 关系状态机按原规则更新，再校验动作。模型不能自选工具、安排时间或直接改变好感/关系状态。Inner OS 关闭或结果无效时采用该场景的保守默认动作。
4. 微信和网页的普通回复、微信的显式预约跟进共用一条生成链路。稳定的表达原则在 [SOUL.md](../config/SOUL.md)，修改后重启。每次请求会用到这段原则、角色资料和当轮有效事实，历史以实际说话人的消息传入。向量与关键词从允许召回的资料中挑选相关原句。摘要、未证实的助手猜测和已撤销的来源不能充当个人事实。日期、事件状态、关系决定和表达偏好各有归属。
5. 草稿交给当前聊天 provider 做一次输出审查。默认 `adaptive` 仅在没有行为计划、来信与草稿都是白名单短确认时跳过。审查可以保留或修订，8 秒超时、截断或协议错误进入既有降级处理。审查后的文字再经过各通道出站保护。微信按实际送达内容记账，网页记录最终回复；审查失败不会生成成功执行记录或新预约。
6. 记录模型成本时，`ai_usage_events.purpose` 区分 `internal`、`reply`、`review`。已有历史行默认显示为 `reply`，无法据此追溯过去每次调用的真实用途。probe 模式跳过用量写入。

例如：“工作搞砸了，我特别委屈”先接住处境；“嗯”延续倾听；明确求建议时才给一个小选择；“别再问了”停止旧事；换到普通话题后不会因下一句“好的”复活旧方案。

V1 采用保守的关键词及上下文规则，不能承诺识别所有自然语言。现有安全检测命中（包括某些含“难受”的表述）和未成年人模式优先，跳过此行为规划；危机场景走既有安全响应。复杂混合情绪和细致语义判定留在 V3。

## 后续关心

仅微信支持后台跟进，要求当前角色绑定有效、允许主动消息且未静默。用户需明确提出整数相对时间，例如“工作搞砸了，30分钟后再问我”，范围 1–1440 分钟。纯转述、否认、未明确的“晚点/明天晚上”和小数时间不安排。网页不安排后台任务，也不让回复承诺已经设好提醒。

任务直接接入现有主动调度，无需等待随机日程命中；仍遵守主动时间窗、睡眠、安全、频率、关系边界和微信会话有效期。因此它是允许范围内尽力跟进，不是精准闹钟。到期后 6 小时未执行则失效；领取租约 5 分钟，失败/暂缓后至少 10 分钟再试。

明确停止/换话题、安全风险、失去绑定或推送权限会阻止旧任务继续执行；普通闲聊或短确认不会擅自取消已经明确约定的跟进。新预约替代旧预约。取消发生在旧回复生成或发送期间时，旧计划不能重新落库或排期。发送前再次检查状态；已提交给微信的在途请求无法撤回。

跟进禁用 iLink 内存发送队列，只有确认投递才记为已发；部分送达记录实际文字，不重发整段。进程在网络确认和数据库记账之间崩溃仍存在分布式投递的不确定窗口，V1 不声称端到端 exactly-once。

## 数据与验证

独立 SQLite 表：`behavior_deliveries` 保存来源、动作、有限的脱敏上下文及实际文本；`behavior_followup_tasks` 保存预约、领取、取消、失效和投递状态；`behavior_state_resets` 保存停止标记。按 companion 隔离，与个人记忆分开，不记录推测的心理效果。近期行动读取窗口为 6 小时，历史表目前不自动清理，运维需按部署的保留策略管理。

probe 模式不写行为、关系状态、对话或模型用量账本。停止标记不算成功执行，因此最新执行记录仍可能是暂停前的动作；读取当前状态必须用 `readBehaviorState`，不能直接取最新执行行。

```sh
npm run check:behavior
```

包含运行时、嵌套 Inner OS 协议、真实临时 SQLite 任务、微信管线投递边界、真实网页管线与本地 HTTP 模型替身、主动消息失败和部分投递回归。无需真实模型密钥，不连接微信。相关既有冲突、安全、隐私、主动消息和探针回归另外执行。
